# Breast Cancer Diagnostic Data — Cleaning & Visualization

A data cleaning, exploratory analysis, and visualization project built on a
real, publicly available clinical dataset. This is a first-year AIML /
data-analysis portfolio project focused on demonstrating practical skills in
**Pandas, NumPy, Matplotlib, and Seaborn** — not on building a predictive
model.

## Overview

Given a real dataset of 569 breast tumor diagnostic measurements, this
project inspects it, documents its actual data-quality characteristics
(rather than assuming or inventing problems), processes it (removing
genuinely redundant features backed by correlation analysis), explores it
statistically, and visualizes it to answer specific questions about what
separates benign tumors from malignant ones.

## Objective

- Practice the full real-world data workflow: inspect → clean → process →
  analyze → visualize → report.
- Extract only findings that are directly computable from the data — no
  fabricated statistics, no invented data-quality problems.
- Produce a small set of visualizations that each answer one specific
  analytical question, not decorative charts.

## Dataset

**Name:** Breast Cancer Wisconsin (Diagnostic) Data Set
**Rows / Columns:** 569 patients × 31 columns (30 numeric features + 1
diagnosis label)
**Source:** [UCI Machine Learning Repository](https://archive.ics.uci.edu/dataset/17),
donated by Dr. William H. Wolberg, W. Nick Street, and Olvi L.
Mangasarian (University of Wisconsin). Distributed via
`sklearn.datasets.load_breast_cancer` under a BSD-style license — free to
use and redistribute with attribution.

Each row is one patient. Ten real-valued measurements were computed from a
digitized image of a fine needle aspirate (FNA) of a breast mass:
`radius, texture, perimeter, area, smoothness, compactness, concavity,
concave_points, symmetry, fractal_dimension`. Each measurement is reported
three ways — `mean_`, `_error` (standard error), and `worst_` (largest
value) — giving 30 numeric columns, plus the binary `diagnosis` label
(`benign` / `malignant`).

**A note on honesty:** this is a curated research dataset, so it genuinely
contains **zero missing values and zero duplicate rows**. Rather than
injecting artificial problems to "demonstrate cleaning," this project runs
the full missing-value and duplicate checks and reports that true (negative)
result — the skill being demonstrated is knowing *how* to verify data
quality quantitatively, not assuming it. The dataset does contain real
statistical outliers and real multicollinearity between features, which are
detected, analyzed, and handled deliberately (see below).

## Data Cleaning Methods

| Step | Finding | Action |
|---|---|---|
| Missing values | 0 across all 31 columns | None needed (verified, not assumed) |
| Duplicate rows | 0 exact duplicates | None needed (verified, not assumed) |
| Column names | sklearn exports space-separated names (`"mean radius"`) | Standardized to `snake_case` (`mean_radius`) |
| Data types | `diagnosis` was a plain text/object column | Converted to a pandas `category` dtype |
| Redundant columns | `mean_radius` / `mean_perimeter` / `mean_area` correlate at r > 0.98 (and likewise for `worst_`) — geometrically near-duplicate measurements | Dropped `mean_perimeter`, `mean_area`, `worst_perimeter`, `worst_area` (31 → 27 columns), keeping `radius` as the representative measure |
| Outliers | 29 of 30 numeric columns contain IQR-flagged outliers; the 65 outliers in `area_error` are **100% malignant cases** | **Detected and reported, not deleted** — these are real, clinically significant extreme values, not data-entry errors. Deleting them would remove the most important cases in the dataset. |

Full before/after shape and quality comparison is in the notebook.

## Key Findings

1. **Moderate class imbalance:** 357 benign (62.7%) vs. 212 malignant
   (37.3%) cases — relevant for any future modeling (a "predict benign
   always" baseline would already score ~63% accuracy).
2. **The dataset is genuinely clean:** 0 missing values, 0 duplicates
   across 569 rows.
3. **Shape irregularity beats raw size as a diagnostic signal:**
   `worst_concave_points` correlates with malignancy at r = 0.79, ahead of
   `worst_perimeter` (0.78) and `mean_concave_points` (0.78).
4. **Some features carry almost no diagnostic signal:** `symmetry_error`,
   `texture_error`, `mean_fractal_dimension`, and `smoothness_error` all
   correlate with diagnosis at r < 0.08.
5. **Malignant tumors are dramatically larger and more irregular on
   average:** mean radius +43.8%, mean area +111.4%, mean concave points
   +238.5% vs. benign.
6. **Radius, perimeter, and area are nearly the same measurement**
   (r = 0.998 between mean radius and mean perimeter) — the basis for
   dropping redundant columns during cleaning.
7. **Outliers are clinically real, not noise:** every one of the 65
   IQR-flagged outliers in `area_error` is a malignant case.
8. **Outliers are the norm across the feature set:** 29 of 30 numeric
   columns contain at least one flagged outlier (median ~3.1% of rows per
   column), consistent with naturally right-skewed biological data.

See the notebook's **Key Insights** section for the full observation →
evidence → interpretation → why-it-matters write-up for each finding.

## Limitations

- The dataset, as sourced, has no real missing values or duplicates, so this
  project cannot demonstrate imputation strategies (mean/median/mode fill,
  etc.) on genuine missing data — only the *detection* methodology is shown.
- No predictive model is trained; this is a cleaning/EDA/visualization
  project by design, not a classification project.
- Outlier handling here is a judgment call (detect + keep, with reasoning)
  rather than a single universally "correct" answer — a different analyst
  could reasonably choose to cap or winsorize instead.
